# Machine notes

Part of the project's instructions for Claude Code; the core is `CLAUDE.md` at the repository root, the index of these files is its section "Further documentation".

| Machine | Master clock (PAL) | Gotchas |

| C64 | CPU 985 248 Hz | Bad lines steal CPU cycles; sprite DMA; `$01` port banking; optional SD2IEC on the serial bus (`sd2iec=on`, device 9, or `drive8=sd2iec`; see `devices.md`) |
| Ultimate 64 / Commodore 64 Ultimate (`ultimate64`, models `u64`, `c64u`; in `machine-c64`) | the C64's; the turbo CPU makes 1–48 (c64u: 1–64) CPU cycles in one VIC-II cycle | A board setting of the C64 (`C64::new_ultimate`), not an own machine struct: every C64 option applies, `uci` is on by default. Turbo (`machine-c64::turbo`, options `turbo=off\|manual\|registers\|enablebit`, `cpu_speed`, `badlines`): the 1 MHz cycle runs as on a C64, then `C64::turbo_cycles` runs the extra CPU cycles on a `TurboBus` that lets only internal memory through (RAM, KERNAL, BASIC, character ROM); the first access to I/O or cartridge ROM is taken back (the CPU is restored from a copy) and made in the next 1 MHz cycle. With `badlines=off` the CPU also runs while BA is low. The chips do not advance between turbo cycles. Registers `$D030`/`$D031`/`$D07A`/`$D07B` sit in `Io` before the VIC-II's decoding; savestate chunk `U64T` at the end of the state. Unverified points are listed in `turbo.rs`. Frontend tables that go by machine id (`media-backends::roms`, `mimic-input` keymap and joystick port, `video-crt` profile) name `ultimate64` next to `c64`. Menu (`machine-c64::u64menu`): panel control 5 "MENU"; while it is open `C64::frozen` stops the CPU in `cycle` (the chips run on), key presses go to `C64::menu_key` instead of the matrix (releases reach both), `menu_frame_tasks` draws it once a frame into `menu_frame`, which `framebuffer` then returns; what the menu wants done comes back as a `u64menu::Action` (`menu_action`). Files only through the host services (`device_host().files`, the UCI's folder), so recordings replay. The updater's flash is `/Flash/.firmware` there (own format); `Flash::Damaged` keeps the board frozen on its notice. Update files (`u64menu::inspect_image`, after the firmware's loader): blocks of load address, length, start address and the bytes; `.cfw` with 36 bytes in front (`DE AD 15 41`, product family, product name; 16 bytes each). The u64 (family U64MK1) takes `.u64`, the c64u (family U64MK2) `.ue2`, both any `.cfw` whose family and name fit. Savestate chunk `U64M` after `U64T` |

| Robotron KC85/2, /3, /4, /5 | U880 (Z80) 1.75 MHz (/2, /3), 1.7734475 MHz (/4, /5) | Models "2", "3", "4" (default), "5". `step_timed` (2026-11-19, before: whole instructions): CTC, PIO, tape, sound, keyboard, beam and the D004 catch up before I/O, the interrupt acknowledge and writes to $8000–$BFFF; the D004's Z80 likewise before its I/O. Interrupt mode 2 through CTC and PIO (`chips-zilog`); the machine finds RETI by the bytes at PC. PIO A and B and ports `$84`/`$86` switch the memory; a PIO port drives its lines the moment it becomes an output, so the output register comes first. Power-on enters at `$F000`, RESET at `$E000`. The picture is drawn line by line at each line's end; the /2 and /3 spread the line number over the IRM address, the /4 stores columns. Keyboard: serial pulses at PIO B's strobe, timed by CAOS with CTC 3 (25 ms of silence between keys, CAOS 3.1 needs it). Tape: a strobe at PIO A per zero crossing, CTC 2 times the half waves (the blink stops meanwhile). CAOS 3.1 needs about 350 fields to its menu. D004 (`d004=on`): a second Z80 at 4 MHz run in step after every KC instruction; it boots by sliding over its cleared RAM (NOPs) into the Koppel-RAM at `$FC00`; the KC's RESET does not reach it. Details and what is unchecked: `phases/phase-25-kc85.md`. |

Model variants (Kernal revisions, RAM sizes) are **configuration**, not separate machine crates. PAL or NTSC is `--videoformat pal|ntsc|auto` (`MachineConfig::video_format`, `MachineEntry::video_formats`; `Registry::create` refuses it on machines with one format and refuses `--model pal` and `ntsc`), never a model name.
