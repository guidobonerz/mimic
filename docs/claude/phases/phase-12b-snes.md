## Status

User choices: NTSC and PAL; the SPC700's 64-byte boot ROM user-supplied (role "spc700") with this project's own loader for the documented upload protocol when it is missing; of the coprocessors only the DSP-1; joypad, mouse, Multiplayer 5 and Super Scope. Done: `cpu-65816` (all 5 080 400 Harte tests, every bus cycle including the internal ones' addresses), `cpu-spc700` (all 256 000 Harte tests with dummy reads), `chips-nintendo::sdsp` (BRR, Gaussian interpolation with the documented table, ADSR/GAIN, noise, pitch modulation, echo with FIR), `chips-nintendo::sppu` (modes 0–7, 16×16 tiles, offset-per-tile, Mode 7 matrix and screen-over, sprites with the 32/34 limits and flags, windows, colour math, mosaic, direct colour, hires and pseudo-hires, interlace; a line at a time), `devices-cartridge::snes` (LoROM/HiROM/ExHiROM, SRAM, copier header, header scoring), `devices-input::snes` (`PortKind::SnesControl`), `machine-snes` (bus speeds, refresh, DMA/HDMA, NMI/IRQ/H/V timers, multiplier/divider, auto joypad, Multiplayer 5, Super Scope latch, S-SMP with timers and ports, 32 → 48 kHz resampling, debugger targets cpu and spc700 with spaces cpu/vram/cgram/oam/aram, savestates). A user-supplied game (Sonic the Hedgehog 4 (Unl), LoROM) runs from the title screen into the level with sound. Since 2026-11-09 also: the NEC DSP boards (new `cpu-upd7725`, the µPD77C25 with its user-supplied program ROMs `dsp1`/`dsp1b`/`dsp2`/`dsp3`/`dsp4`, 7.6 MHz, caught up at register accesses and every line; `machine-snes/src/dsp.rs`, debug target `dsp` with space `dsp-ram`; board chosen by title, registers by board layout in `devices-cartridge::snes`); the DSP-1B program computes multiply, sine/cosine, distance and inverse correctly in `cpu-upd7725`'s tests (no DSP game of the user's tried yet); a DSP game without its ROM is refused at insertion. Battery SRAM goes to a `.srm` file beside the image (new media kind `BatteryRam`, slot `SLOT_BATTERY`, `media_backends::image::attach_battery_ram` in desktop and headless; written at the end of every frame the game changed it, kept through power cycles; the web frontend has no file for it yet). The multiplier and divider work one bit per CPU cycle (8/16 cycles, partial results readable). Open: other coprocessors (Super FX, SA-1, Cx4, ST010/011/018 …) refuse to load; mid-line PPU register changes (the PPU draws a line at a time). Test ROMs since 2026-11-09: gilyon's snes-tests (`tests/tests/snes_tests.rs`) cputest-basic, cputest-full and spctest all Success (one 65816 fix: `(dp,X)` in emulation mode with DL not zero wraps the pointer's high byte within the page, as on hardware; the 264 Harte cases with the opposite skipped as contradicting hardware); PeterLemon's ROMs with reference pictures (`tests/tests/snes_peterlemon.rs`) 59/78 after BG lines were moved to VOFS + y (they were one line low), 67/78 later on 2026-11-09: modes 5/6 in interlace show the BG at 448 lines (line 2·y + field), OBJ interlace (SETINI bit 1) shows every other sprite line per field, hires mosaic counts in 512-wide pixels; the runner holds R in the mosaic demos until MOSAIC = $F1, presses RESET in CPUMSC after its STP, and runs WaveHDMA/StarWars to the frame their picture shows (185/262, found with `EMU_SNES_SEARCH`). Open there: RotZoom, WindowMultiHDMA and InterlaceScroll show the picture after joypad input that is not known; HiColor1241DLair's picture is one line lower than all others (row 0 backdrop); InterlaceFont's picture has a different glyph geometry; InterlaceMoogle differs only in edge pixels (~20 levels); the pseudo-hires HiColor ROMs (4) differ where HDMA rewrites CGRAM mid-line (needs dot-wise drawing); Perspective's PNG is broken in the repository; the SPC700 ROMs need up to 3000 frames with the machine's own IPL loader.

## Backlog detail

- **Super Nintendo (SNES/Super Famicom)** (Phase 12b, added 2026-10-23): three processors — the 5A22 (65C816 core with DMA/HDMA), the S-SMP (SPC700) with the S-DSP and its own 64 KB audio RAM — and two PPUs sharing `chips-nintendo` with the NES; cartridge coprocessors (DSP-n, Super FX, SA-1, S-DD1, Cx4) as `devices-cartridge::snes` types, only DSP-1 planned in the phase; ROMs (games) user-supplied, the SPC700 IPL ROM is 64 bytes inside the chip (user-supplied too).
