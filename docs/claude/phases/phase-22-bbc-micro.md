## Backlog detail

- **Acorn BBC Micro** (added 2026-10-27 on the user's request, Phase 22): Model B, B+ and Master 128 (Electron later) as models of one machine; 6502 at 2 MHz (reuse `cpu-6502`; the Master's 65SC12 as a CMOS variant), Video ULA and 6845 CRTC (reuse `chips-amstrad`'s CRTC) for modes 0–7 including the SAA5050 teletext mode 7, 6522 VIAs (reuse `chips-cbm`) for the keyboard, sound, speech, user port and printer, SN76489 sound (reuse `chips-ti`), 6850 ACIA with cassette and RS-423, 8271 (Model B) and 1770/1772 FDCs with SSD/DSD/ADF images, Tube later, sideways ROMs/RAM and the Master's MOS 3.20 banking; MOS, BASIC and DFS/ADFS ROMs user-supplied.

## Status

Begun 2026-11-10 on the user's request. User choices: I look for a source of the ROMs and show it with its licence before anything is downloaded; Model B first (to BASIC and a DFS disk), then the B+ and the Master 128; both disk controllers, the 8271 (Acorn DFS on the Model B) and the 1770 (B+, Master, 1770 DFS boards); mode 7 is checked against the SAA5050 data sheet (its character set and the control code rules), with own test pages as the reference.

ROMs (the user owns them; his copies in `~/.mimic/roms/bbc`, never in the repository): MOS 1.20 `os12.rom`, BASIC II `basic2.rom`, Acorn DFS 1.20 (8271) `dfs-1.20.rom`, Acorn DFS 2.26 (1770) `dfs-2.26.rom`, the B+ MOS `bplus-mos.rom`, the Master 128 MOS 3.20 set in `master320/`.

Milestones:
Done 2026-11-10: M1 — the Model B boots MOS 1.20 to BASIC II with the user's ROMs ("BBC Computer 32K", "BASIC", the prompt), BASIC computes `PRINT 1+2`, `MODE 2` + `GCOL 0,129:CLG` fills the screen red, MODE 1 text is right (`tests/tests/bbc_boot.rs`, 3 tests; `machine-bbc` 7 tests with the stub MOS; `chips_acorn::VideoUla` 3 tests). The 6850 answers its status at rest until M3 (the MOS polls it in its interrupt handler). Open in M1: the cursor not yet seen on a picture (blink phase?), the hardware wrap-around sizes unchecked by a scrolling test.

Done 2026-11-10: M2 — `chips_acorn::Saa5050` after the Mullard data sheet (July 1982): the English character set of Fig. 11 read dot by dot from the scan (94 automatically, `7` and `?` by eye), the control codes of Table 1 with the teletext set-at/set-after rules, contiguous and separated mosaics (Fig. 9/10), blast-through, hold graphics, double height over two rows, flash 3:1 at ~0.75 Hz, conceal, character rounding to 12 × 20 half dots (7 unit tests). The machine routes teletext through it (the row's scan line from RA, in half lines when the 6845 interlaces). The boot screen shows "BBC Computer 32K", "BASIC" and the cursor; the mode 7 test page (`mode_7_test_page_matches_its_reference`: double height, colours, backgrounds, all mosaics, hold, blast-through, flash, the whole character set) is fixed by its picture hash after checking it by eye. Open in M2: the 6845's display and cursor skew (R8) not modelled, the separated-graphics gap side and the exact rounding half-dot placement taken as described, not compared with a real picture.

Done 2026-11-10: M3 — the 6850 ACIA (`machine-bbc/src/serial.rs`, after the Motorola data sheet: status, control, master reset, receive/transmit/DCD interrupts, overrun, the receiver held in reset while DCD is high) on the IRQ line with the VIAs; the serial ULA at `&FE10` (motor relay bit 7, RS423/cassette bit 6, rates); the cassette recorder as media slot "cassette" (`machine_bbc::SLOT_CASSETTE`, `.uef` plain or gzip and `.wav` through the new `media::uef`; keys play/record/stop/rewind, insert presses PLAY, recording rewrites the tape from where it began and goes back to the medium as an uncompressed UEF on stop, rewind, flush or eject; an empty file is a blank tape). The run-in detector raises DCD after 24 bit times of unbroken carrier and drops it at the first start bit (the hardware guide names the detector but not its time; 24 is this project's choice). `basic_saves_and_loads_on_tape`: `SAVE "T"` on a blank tape (RECORD then RETURN, block counter `T 00 000D`), the UEF written back has leader, `&2A` and the name, `LOAD "T"` and `LIST` show the line again. Sound: `basic_sound_plays_a_tone` (`SOUND 1,-15,100,20` loud for one second, quiet after). The user VIA is there (port lines unconnected). Open in M3: the tape is fed as whole bytes (no tone-level modelling of the serial ULA, so copy-protection loaders that measure tones and the 300-baud bit-3 tone swap are not covered); RS423 has no device behind it; the WAV decoder is checked with synthetic tones only, no real recording yet.

Done 2026-11-11: M4 — `chips_acorn::I8271` after the Intel *Peripheral Design Handbook* (1979): status, result codes, the command set with its parameters (read/write/verify for 128-byte and variable records, read ID, format, seek, read drive status, specify, read/write special register; scan answers "not met"), non-DMA data requests with INT per byte, late DMA, bad tracks, single-density timing (64 µs per byte, 300 rpm, step rate and settling time from specify). INT drives the 6502's NMI. `machine-bbc/src/disc.rs`: two drives as media slots "drive 0"/"drive 1" (`SLOT_DRIVE0`, `SLOT_DRIVE1`), SSD and DSD images (by extension; short images padded to 40/80 tracks, an empty file a blank 80-track disc; side 1 through the 8271's OPO line as DFS drive 2/3). DFS 1.20 (optional ROM role `bbc-dfs`, `dfs-1.20.rom`) sits in sideways slot 14; without it the machine has no disc interface. Tests: 4 unit tests for the 8271, `shift_break_boots_a_dfs_disc` (boot option 3, `*EXEC !BOOT`), `basic_saves_and_loads_on_disc` (SAVE, `*CAT`, LOAD, LIST, the catalogue written back), `a_savestate_in_the_middle_of_a_disc_read_resumes_it`. Open in M4: the drive status / input port bit order is the commonly documented one (the handbook's figure was not legible in the scan); sector-level images only (no copy-protected discs, formats only fill sectors the image holds); scan commands not modelled; no real commercial disc tried yet.

Done 2026-11-11: M5 — models `--model b` (default), `bplus` and `bplus128`. The B+: 20 KB shadow RAM behind &3000–&7FFF (ACCCON &FE34 bit 7: display and the VDU driver's accesses; code counts as VDU driver when its opcode comes from &C000–&DFFF, or &A000–&AFFF with the private RAM in), 12 KB private RAM at &8000–&AFFF (ROMSEL bit 7), MOS 2.00 (role `bbc-bplus-mos`, `bplus-mos.rom`). The B+ 128 adds 16 KB sideways RAM in slots 0, 1, 12, 13 (in the savestate; MOS 2.00 reports "Acorn OS 128K"). The 1770 (`chips_acorn::wd1772`, now with single density: 64 µs a byte) at &FE84–&FE87 with the drive control latch at &FE80 (drive select bits 0/1, side bit 2, single density bit 3, reset bit 5), INTRQ or DRQ on NMI, DFS 2.26 (role `bbc-dfs226`, `dfs-2.26.rom`) in slot 14. Found on the way: DFS 2.26 looks for its 1770 by the track register holding &5A and `&FE80 AND 3` ≠ 0, so the write-only latch reads &FF. The debugger's CPU space shows main RAM at &3000–&7FFF; the shadow and private RAM have their own spaces ("shadow", "private"). Tests: 3 unit tests (shadow rule, private RAM, sideways RAM with savestate), `bplus_boots_to_basic`, `bplus128_boots_to_basic`, `bplus_shadow_mode_writes_the_shadow_ram` (MODE 135, HIMEM &8000), `bplus_boots_and_saves_on_the_1770` (SHIFT+BREAK, SAVE/LOAD in single density). Open in M5: the reset bit's polarity (any change resets), bit 4 of the latch, the 1770's step rates (the 1772's are used) and double-density discs on the B+ (ADFS is the Master's, M6) are not checked against hardware; the VDU rule is taken at the instruction's opcode fetch, interrupts included.

Done 2026-11-11: M6 — `--model master`: the 65SC12 (`cpu-6502` CMOS variant), MOS 3.20 from its 16 KB pieces (roles `master-mos`, `master-dfs`, `master-viewsheet`, `master-edit`, `master-basic`, `master-adfs`, `master-view`, `master-terminal`; folder `bbc/master320`) in banks 9–15, sideways RAM in banks 4–7. ACCCON at &FE34 after the *Advanced Reference Manual*: D displays LYNNE, E sends the VDU driver's accesses (opcode from &C000–&DFFF) there, X all of them, Y pages HAZEL over &C000–&DFFF, IRR pulls IRQ; it reads back (MOS 3.20 changes it with TSB/TRB). ROMSEL bit 7 pages ANDY (4 KB at &8000–&8FFF). The MC146818 clock with its 50 bytes of CMOS RAM (`chips_acorn::mc146818`) on the slow data bus (CE PB6, AS PB7, R/W latch bit 1, DS latch bit 2, data port A), counting machine cycles from `--option rtc=YYYY-MM-DD[THH:MM[:SS]]` (default 2000-01-01; MOS 3.20 shows no century). The 1770 at &FE28–&FE2B with the drive latch at &FE24 (drive bits 0–2, reset bit 3 low, side bit 4, single density bit 5). ADFS images `.adf` (S/M) and `.adl` (L). Only the system VIA and the 1 MHz bus are slow on the Master. Found on the way: MOS 3.20's "R power-on" only blanks the CMOS RAM (MOS 3.50 restores defaults), so a new Master starts with the bytes MOS 3.20's own `*CONFIGURE` writes for LANG 12, FILE 9, MODE 7 and the usual settings (`--option cmos=blank` for the blank RAM); the keyboard's autoscan now steps a 1 MHz column counter, so CA2 makes edges for a key held from power-on (as the MOS's BREAK+key detection needs). The CPU space of the debugger shows main RAM at &3000–&7FFF; LYNNE is "shadow", ANDY "private". Tests: 2 unit tests (paging, savestate with CMOS and clock), 3 for the MC146818, `master_boots_to_basic`, `master_boots_and_saves_on_dfs`, `master_saves_and_loads_on_adfs` (an empty L disc built in the test: old map with checksums, "Hugo" root), `master_shadow_mode_writes_lynne`, `master_time_comes_from_the_clock`. Open in M6: the CMOS RAM is not kept between sessions (only in savestates); the Master's keypad keys and the host mapping, the ADC (uPD7002 at &FE18), Econet, the internal Tube and the cartridge sockets are not there; the clock's alarm interrupt (link 4) and periodic rates are not wired; the VDU rule is taken at the opcode fetch, the manual's "in RAM" detail of that rule not followed up.

Done 2026-11-11: M7 — graphics views (`machine-bbc/src/gfx.rs`): `screen` (the picture the 6845 and the Video ULA make from memory now: R12/R13 or option `addr`, R1 × R6 characters, the ULA's pixel rate and palette, the wrap-around, the shadow RAM as displayed; teletext through a fresh SAA5050 in all 20 half lines), `palette` (16 logical colours as physical ones), `charset` (the SAA5050's 96 alphanumerics and the contiguous graphics set); debugger chips `sysvia`, `uservia`, `sn76489`, `i8271`/`wd1770` (status, track, sector, data, control, INTRQ/DRQ), the ULA's 16 colours. The Master's keypad (columns 10–12) after the *Master Reference Manual* part 1, every key checked with MOS 3.20 (`master_keypad_types_digits_and_operators`); on the B and B+ its digits, `-`, `/`, `.`, `,`, RETURN and DELETE type the main keys. BREAK as machine key 0x100 (host Pause). Desktop (user decision 2026-11-11): F9–F11 are no longer datasette hotkeys, so f9/f0 reach the BBC (and the CPC its f9/f0); every tape slot has Play/Rec/Stop/Rew buttons on a line of its own in the media panel. User guide (en/de) with models, ROM files, options and keys; README with screenshots (`docs/screenshots/bbc.png`, the mode 7 test page, `EMU_SNAPSHOT_DIR` with `mode_7_test_page_matches_its_reference`; `bbc-master.png`, the Master after `*TIME`, with `master_time_comes_from_the_clock`), `docs/usage.md` with the BBC's ROMs, models, options, media and keys and the BBC rows. **The gate is met** (2026-11-11): all three models (and the B+ 128) boot to BASIC with real ROMs, a DFS disk boots with SHIFT+BREAK (8271 and 1770), mode 7 matches its reference picture. Tests: `machine-bbc` 19, `bbc_boot` 19. Still open after the gate: the CMOS RAM between sessions (needs a host storage path like the Archimedes' CMOS, neither has one), Tube, Econet, ADC/joysticks, speech, the cartridge sockets, the clock alarm interrupt, commercial discs and tapes, the items listed under M1–M6.

- M1 Model B to BASIC: 6502 at 2 MHz with the 1 MHz bus stretch, memory map and sideways ROM banking (ROMSEL), the 6845 (reuse `chips-amstrad`) and the Video ULA (modes 0–6), the system VIA (keyboard matrix, addressable latch, vsync interrupt), a stub ROM for tests.
- M2 Mode 7: the SAA5050 after its data sheet (character set, graphics, hold graphics, double height, flash, character rounding), own test pages as references.
- M3 Sound and cassette: SN76489 through the slow data bus (reuse `chips-ti`), the 6850 ACIA with the serial ULA and the cassette (WAV/UEF), the user VIA.
- M4 Disks on the Model B: the 8271 with DFS 1.20, SSD/DSD images; a DFS disk boots (`SHIFT+BREAK`).
- M5 B+: 64 KB with shadow RAM, the 1770 (reuse `chips-acorn`) with DFS 2.26.
- M6 Master 128: 65SC12 (`cpu-6502` CMOS variant), MOS 3.20 banking (ACCCON, ROMSEL, private and shadow RAM), CMOS RAM and clock, ADFS.
- M7 Frontends, debugger targets, graphics views, docs, screenshot. Gate.
