## Status

User choices: the IMSAI 8080 instead of the Altair 8800; no monitor, so the switches take the screen's place; the front as on the user's photograph. Done: `cpu-8080` (all 256 opcodes with aliases; TST8080, 8080PRE, CPUTEST and 8080EXM pass with the published T-state totals; the status word of every machine cycle goes to `StatusBus::cycle`), `machine-imsai` (`panel`, `terminal`, EXAMINE/DEPOSIT/STEP/RESET/RUN/STOP/PWR, sense switches, programmed output, program and tape slots, savestates), `emu_core::font` (moved from `machine-apple2`), the manual's test program and Kill the Bit toggled in by tests, clicks on the picture through `InputEvent::LightPen` on port 0 (`Profile::for_options`). The gate is met: Altair BASIC 3.2 (4K; Bruce Hall's IMSAI port, `basic-tape.hex`) prompts, takes a program and runs it on the terminal (a FOR loop on a single line runs once: its own bug, noted in the listing), which also confirms the console at $02/$03; the MPU-A/B monitor ROMs from the same repository run as option `mpu` (MPU-B started and tested, MPU-A only loaded by unit logic; both are z80pack's images, the machine works without them). The mapping (ROM at 0 and $D800, port $F3) comes from the listings; RESET mapping it in again is an assumption. Added 2026-11-08 on the user's request: the IMSAI FIF floppy interface on port $FD (`machine-imsai::fif`; it is the real controller, which z80pack emulates at the same command level, not a z80pack invention): single-byte commands and the 7/9-byte command strings fetched by DMA, status codes, write protection, four 8-inch drives as slots A:-D: (raw IBM 3740 images, 256 256 bytes), timing from the firmware and the drive (6 ms a step, 10 ms settle, 16 ms head load, 360 rpm), the CPU held in WAIT by an OUT while the FIF works, and the firmware's bootstrap DMA'd into memory at power-up and RESET when drive A holds a disk; CP/M 2.2 (z80pack's IMSAI disk) boots both through that bootstrap and through the MPU-B monitor's own boot and runs DIR and STAT (`tests/tests/imsai.rs`, `cpm_boots_*`); Bruce Hall's B03 system disks boot too, but their PROFILE.SUB runs LEDSOFF from drive I:, his IMSAI 8080esp's hard disk, which this IMSAI does not have ("Bdos Err On I: Bad Sector"). The 8251s now take mode and command words (`usart`: after reset waiting for the mode, transmitter and receiver off; character length masks data; the character time follows the mode), which showed a bug in Bruce Hall's Altair BASIC port (`LDA 0CAh`/`LDA 27h` for `MVI A`: on an IMSAI it would print nothing; the test corrects the two opcodes in the loaded image); the MPU-B's 8253 at $D100-$D103 (`pit`, 2 MHz, the clock of its 8251's character time), there while the ROM's upper copy is ([S]: z80pack's 54K CP/M has its BIOS on that page and the MPU-B boots it after removing the ROM); the ROM's copy at 0 leaves at the CPU's next read from $D800-$DFFF after OUT $F3 bit 6 ([S] jump-start latch: the monitor's start fetches its JP from the copy right after the OUT; before, the CPU ran through empty RAM up to $D800); the paper tape punch on the reader channels' data ports (slot "punch": into the file from its start up to its end, "rewind"); PROTECT/UNPROTECT controls for the 1 KB block of switches A10-A15 (in the panel strip, the IMSAI's panel has no such paddles). Added 2026-11-08 with Phase 32: a card reader (slot "cards", `cardreader`; see `phase-32-keypunch.md`). Still open: the FIF's interrupt jumper, read-all's raw track data, logical tracks other than the physical one; the 88-SIO status bits are unconfirmed; LED brightness `sqrt(duty)` is this project's choice; the 26 controls are marked `ControlInfo::on_picture`: the desktop's strip and the web page leave them out, the debug protocol and the preview viewer keep them.
