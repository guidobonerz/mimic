# Phase 33: MEGA65 (and the Commodore 65)

Part of the project's instructions for Claude Code; the core is `CLAUDE.md` at the repository root, the index of these files is its section "Further documentation".

## Decisions (user, 2026-11-11)

- **ROMs:** both. First the Open ROMs (LGPL-3, the user's copy of the 2021-08-23 release in `~/.mimic/roms/mega65/mega65.rom`, 128 KB), then the official closed ROM 920xxx once the user puts it in the same folder; the gate is with the official ROM. Neither is committed.
- **Start:** direct. The emulator puts the 128 KB ROM at `$20000`–`$3FFFF` and resets the CPU; the hypervisor services that ROMs call (drives, D81 mounting) are modelled where needed. The real hypervisor (Hyppo/HICKUP from an SD card image) is a later milestone.
- **Scope:** the full MEGA65 and the Commodore 65 as a model (4510 at 3.5 MHz, VIC-III only). **2026-11-11, the user: the C65 model is dropped** (no C65 ROM).
- **2026-11-11, the user: M7 is deferred** until the official ROM 920xxx is in the ROM folder (only the Open ROMs of 2021-08-24 are there, now with their whole release: `mega65_orfont.rom` and the C64 builds `kernal_generic`, `basic_generic`, `chargen_*`, the Ultimate 64 variants). M8 waits for the hypervisor file (`HICKUP.M65`) for the same reason; M9 goes ahead.
- **Checks:** the user has a real MEGA65; I write measuring programs for it (as with the A500/A1200). Sources are the MEGA65 documentation; no code from Xemu or the VHDL core (golden rule 7).

## Milestones

- M1 `cpu-45gs02`: the 4510 instruction set (A, X, Y, Z, B, the E flag and 16-bit stack, long branches, BSR, word ops, RTS #n, the stack-relative mode), MAP/EOM with the interrupt lock, the 45GS02 extensions (the `NEG NEG` prefix for the 32-bit Q instructions, the `NOP` prefix for flat `[zp],Z`), the cycle counts of the documented tables at 1, 2, 3.5 and 40 MHz, per-cycle stepping; own per-instruction tests; the 6502 personality (undocumented opcodes) later.
- M2 Memory and a first boot: the 28-bit address space (chip RAM 384 KB, ROM at `$20000`, colour RAM, the I/O personalities C64/C65/MEGA65 with the VIC-III/IV knock at `$D02F`), MAP translation, `$D030` ROM banking, the C64 port `$00/$01`, the CPU speed registers, two CIAs, a stub ROM; the Open ROMs start.
- M3 VIC-IV: VIC-II and VIC-III compatible modes, then the VIC-IV ones (80 columns, 16-bit character mode, full-colour characters, the 256-colour palette, raster positions and interrupts, sprites), PAL and NTSC; the Open ROMs show their screen.
- M4 Input and sound: the MEGA65 keyboard matrix (with the C65 extra keys), joysticks, paddles, the 1351 mouse; four SIDs.
- M5 The math unit (multiplier, divider), the hypervisor services the ROMs call in direct start (DMAgic moved to M2).
- M6 Storage: the F011 floppy controller with D81 images (internal drive), the SD card controller with an image, the IEC bus with a 1541 (`drives-cbm`).
- M7 The official ROM 920xxx (BASIC 65, the monitor), the C64 mode (`GO64`). (Deferred by the user until the ROM is there; the Commodore 65 model dropped.)
- M8 The hypervisor boot path (Hyppo from an SD card image, with it its SD card file services and disk image attach), the freezer.
- M9 Frontends, debugger targets and graphics views, docs, screenshot. Gate.

## Status

Done 2026-11-11: M9 (without the gate) — graphics views (`gfx.rs`: `screen` the display area drawn from memory now, `charset` 256 characters at the character pointer or option `addr` (the character ROM windows as the VIC-IV reads them), `sprites` the eight VIC-II sprites or option `index`, `palette` a bank, option `palette`), debugger registers for the four SIDs, the F011, the SD controller, DMAgic, the math unit, the keyboard matrix and the hypervisor (traps, error, ROM protection); debug devices `cpu` and, with a true drive, `drive8`. Frontends: the registry, the keymap (M4), the monitor "lite"; `video-crt`'s pixel aspect now treats a progressive signal above 24 kHz (576p) as full lines, so the 720 × 576 picture comes out 4:3 (787 × 576 at scale 1; before 197 wide). Docs: the user guide (en/de) MEGA65 section, `docs/usage.md`, README (screenshot `docs/screenshots/mega65.png`: the Open ROMs' start screen with `--crt lite:1`; test, machine, CPU and chip rows), `crt.md`, `debugger.md`. **The gate is not met** (the user deferred M7 and M8): the official ROM and a D81 load wait for the 920xxx ROM, measurements for the user's MEGA65. Tests: 1 more unit test (the views and the chip list), 1 in `video-crt`.

Done 2026-11-11: M6 — the serial bus with drive 8 (`drives-cbm`'s `SerialDrive`, as on the C64: `--option drive8=1541|1571|1581|virtual|none`, by default a true 1541 when `dos1541` is in the ROM folder's `drives`; CIA 2 PA3–PA5 out, PA6/PA7 in; the drive runs on the 1 MHz cycles; debug device `drive8`, space `drive8`; RESET resets it): **the Open ROMs load from it** — `LOAD "$",8` lists a D64 built in the test and `LOAD "HELLO",8` + RUN runs its program (`open_roms_load_from_a_1541`). The storage controller (`storage.rs`): the F011 with two drives holding D81 images (slots "drive 0 (internal)" and "drive 1"; the C65 specification's registers and commands, the guide's 1581 layout: physical track, side, sector 1–10 of 512 bytes; read, write, steps, spin-up, cancel, buffer pointers, DRQ/EQ/RNF/RDREQ/WTREQ, TK0, DSKIN, DSKCHG, PROT, SWAP, the drive swap at $D689 bit 5; commands finish at once), the SD card controller with a raw card image (slot "SD card"; sector number $D681–$D684, read, write behind the write gates $57 and $4D for sector 0, fill mode, reset, SDHC flag, slot select), the sector buffers by BUFSEL ($D689 bit 7) at $FFD6000–$FFD6FFF and, with command $81, at $DE00–$DFFF. Savestates keep the D81 contents; the SD card's sectors stay in its medium; a state loads with the media taken out of the copy and put back. The frontends' `--disk` passes an image a slot refuses on to the next: D64 to drive 8, D81 to the internal drive, a card image to the SD card. Decided on the way (mine): the hypervisor's SD card file services (HDOS on FAT32) and disk image attach move to M8 — the real Hyppo runs its own FAT32 code over this SD controller, a second implementation here would be thrown away. Tests: 4 more unit tests (D81 read/write and flush, drive swap/not found/steps/wrong size, SD card read/write/gates/fill/mapping, savestates with a floppy), 1 more ROM test. Open in M6: real floppy timing (BUSY, seek, rotation), raw flux and track DMA, MEGA disks, the Open ROMs of 2021 have no D81 support (their README), so the F011 waits for the official ROM to be tried; the desktop's drag-and-drop puts an image into the first drive only.

Done 2026-11-11: M5 — the math unit ($D770/$D774 inputs A and B, MULTOUT $D778 = A × B unsigned 64 bits, DIVOUT $D768 = A / B as 32.32 fixed point, all ones for B = 0 (my assumption), the divider done at once so DIVBUSY at $D70F stays clear); the hypervisor services in direct start (`hyper.rs`): a write to $D640–$D67F in the MEGA65 (or Ethernet) personality runs the service chosen by A after the instruction (the CPU waits 256 master clocks, an estimate), C set on success, else C clear and the error code in A (geterrorcode returns it): getversion (Hyppo 1.2, HDOS 1.2), setup_transfer_area, rom_writeprotect/writeenable/toggle, toggle_force_4502 (only the 45GS02 personality: A bit 5 set), get_mapping/set_mapping, serial_monitor_write and wait_and_write (kept in `Mega65::serial_out`), reset (warm boot), dmagic_autoset (F018B); the SD card, disk image, task, configuration sector and freezer services answer "not implemented" ($82), unknown services "no such trap" ($FF). Found: the Open ROMs (2021-08-24) call no hypervisor service at all, at boot or for LOAD "$" (which fails with ?DEVICE NOT PRESENT until the IEC bus, M6); the services are for the official ROM and programs. Tests: 3 more unit tests (getversion, errors, the ROM protection by trap and in the C64 personality; get/set_mapping; the math unit). Open in M5: the SD card (HDOS file services: M6 with an SD card image), disk image attach (M6 with the F011), the 6502 personality, the configuration sector, the freezer, the programmable math unit ($D780–$D7E3, disabled on the hardware too), the trap's real cycle count.

Done 2026-11-11: M4 — the keyboard (`keyboard.rs`): the C65 matrix of nine columns (columns 0–7 through CIA 1 with the C64's ghosting resolution, column 8 through $D607 bit 1), RESTORE on NMI, CAPS LOCK as a locking key (the C65's CPU port bit 6, $D611 bit 6), the separate cursor left/up keys (right SHIFT + CRSR in the matrix, $D60F bits 0/1), the matrix registers $D614/$D613, the modifiers $D611, the virtual keys $D615–$D617 ($7F none: a start value of 0 held INST/DEL and pulled the Open ROMs' cursor back), the typing event queue $D610 (ASCII after the guide's tables, `keytable.rs` generated by `tools/gen_mega65_keymap.py` from the data the guide's tables are made from), $D619 (PETSCII derived from it), $D60A; the host keymap `mega65` (emu-input: arrows the four cursor keys, Escape ESC, Tab TAB, left Ctrl CTRL, left Windows MEGA, left Alt ALT, End RUN/STOP, Page Up RESTORE, Page Down HELP, Scroll Lock NO SCROLL, Print Screen F13, F1–F11 with SHIFT for the even ones). The control ports as on the C64 (`--option port1`/`port2`: joystick, paddles, 1351 mouse, proportional mice, keypads; a joystick in port 2 by default; port 1 on CIA 1 port B, port 2 on A; POTX/POTY switched by CIA 1 PA6/PA7). Four SIDs (`chips-cbm`) at the C64's rate: right #1/#2 at $D400/$D420, left #1/#2 at $D440/$D460, mirrored at $D480–$D4FF, mixed to stereo; $D63C bits 0–3 select 6581 or 8580 per SID (6581 at reset; `chips-cbm` `Sid::set_model`). **Typing works in the Open ROMs**: a string PRINT, a program line, LIST and RUN (`open_roms_type_list_and_run`); numbers (`PRINT 3`, `A=1`) give the Open ROMs' own "?NOT IMPLEMENTED ERROR" (their BASIC of 2021-08-24 is incomplete, as their README says). Speed: the 2/3.5 MHz cycles are events only at that speed and the read page table for $8000–$FFFF (4 KB pages, recomputed on banking changes) — the Open ROMs at ~62 fields a second (16 ms each; 40 MHz CPU ~9 ms, four SIDs ~2.3 ms, drawing ~1.4 ms). Tests: 5 more unit tests (matrix through CIA 1 and column 8, the typing queue with ASCII/PETSCII and CAPS LOCK, cursor keys/virtual keys/RESTORE, joysticks and pots, four SIDs in stereo and $D63C), 1 more ROM test. Open in M4: the CPU at 40 MHz is the larger part of the time (a further speed-up of `cpu-45gs02` later), the keyboard LEDs ($D61D/$D61E), the on-screen keyboard, the SID extra registers ($D63C bit 4), audio DMA and the digi channels ($D6F8–$D6FB), the keyboard's NMI on long RESTORE (the freezer).

Done 2026-11-11: M2 — `machine-mega65`: chip RAM 384 KB with the ROM at $20000 (write-protected), colour RAM 32 KB with the $1F800 mirror, the VIC-IV character ROM area, the CPU port ($00 = 65/64 forcing 40 MHz), the C64 banking and the VIC-III $D030 ROM bits for unmapped accesses (ROM8/ROMA/ROMC/ROME at $38000/$3A000/$2C000/$3E000 after the C65 specification's mode table; the guide's table says $28000 for ROM8), CRAM2K, the I/O personalities with the KEY knock (C64: $D030 the C128 2 MHz bit, the VIC-III/IV registers and the palette hidden) and their 28-bit addresses $FFD0000–$FFD3FFF, a VIC register file with the raster counter and compare IRQ (`vic.rs`, the picture in M3), two CIAs (`chips-cbm`, 6526A), the speed from $D031 FAST, $D054 VFAST, the C128 bit and the port; master clock 40.5 MHz, fields of 312 × 2596 clocks, the CIAs at 63 cycles a line. **DMAgic moved here from M5** (`dma.rs`): the Open ROMs fill colour RAM with an enhanced job before they print anything; F018 and F018B lists, enhanced jobs at $D705/$D706 and inline at $D707 with the option tokens (megabytes, steps, transparency, format), copy, fill, swap, hold, decrement, the I/O flag, the CPU waiting a clock a byte filled and two a byte copied. Done 2026-11-11: M1 — `cpu-45gs02`: the 4510 instruction set (A, X, Y, Z, B, E flag with the 8/16-bit stack, TSY/TYS, long branches relative to the last byte, BSR, RTS #n, PHW with its byte order, INW/DEW/ASW/ROW, NEG/ASR, RMB/SMB/BBR/BBS, TSB/TRB, (d,SP),Y, STZ storing Z, BIT # setting N and V), MAP with the megabyte extension and the interrupt lock until EOM, flat `[zp],Z` (`EA` prefix), the Q instructions (`42 42`; `(zp)` without Z except LDQ; a `42 42` before an opcode without a Q form is two NEGs), the `$D019` dummy write; bus addresses are 28-bit for mapped and flat accesses and the 16-bit CPU address with `UNMAPPED` set otherwise. Timing: one tick a CPU cycle, all bus accesses in the first cycle, then idle, as the guide says the hardware does at 1–3.5 MHz; counts from the guide's tables (`table.rs`, generated by `tools/gen_45gs02_table.py`; at 1/2 MHz the 6502's, at 3.5/40 MHz the 4510's with the r/i/p/b/d flags; eight evident slips of the 4510 table set to their siblings' values). Tests: 22 own (the guide's MAP, flat and Q examples among them), Dormann's 6502 functional test passes on it. My decisions where the guide is silent, to be measured on the user's MEGA65: decimal N/Z valid (CMOS), interrupts leave D, long branches relative to the last byte, the 45GS02 compound cycle table taken as written (its entries look partly shifted). Not yet: the 6502 personality (undocumented opcodes), the hypervisor mode and traps (M5/M8).
